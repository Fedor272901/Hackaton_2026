# Структура backend-проекта (Hackathon)

Этот документ описывает текущую структуру backend-проекта, назначение каждой папки и файла, а также правила работы с кодовой базой.

Документ является базовой точкой входа для разработчиков и задает единый подход к разработке.

---

# Общая структура

Это минимальный skeleton backend-проекта, который задает архитектуру и разделение ответственности между слоями. Он используется как основа для дальнейшего расширения функциональности и командной разработки.

```
app/
 ├── api/
 │    └── v1/
 │         └── endpoints/
 │              └── users.py
 │
 ├── crud/
 │    └── user.py
 │
 ├── db/
 │    ├── database.py
 │    └── models.py
 │
 ├── schemas/
 │    └── user.py
 │
 ├── api_router.py
 └── main.py
```

---

# Основные файлы

## app/main.py

Точка входа в приложение.

Отвечает за:

- создание FastAPI-приложения
- подключение роутеров

---

## app/api_router.py

Главный роутер приложения.

Отвечает за:

- подключение всех endpoint’ов
- объединение API в единое пространство

Пример:

```python
api_router.include_router(users.router, prefix="/users", tags=["Users"])
```

---

# Слой API (контроллеры)

## app/api/v1/endpoints/

Здесь находятся endpoint’ы (ручки API).

Каждый файл соответствует отдельной сущности.

### users.py

Отвечает за:

- обработку HTTP-запросов
- валидацию входных данных
- вызов бизнес-логики (CRUD)

В этом слое не должна находиться логика работы с базой данных

---

# Бизнес-логика

## app/crud/

Содержит логику работы с базой данных.

### user.py

Отвечает за:

- создание пользователя
- получение пользователя
- обновление пользователя
- удаление пользователя

CRUD — это слой между API и базой данных.

---

# База данных

## app/db/database.py

Отвечает за:

- подключение к базе данных
- создание engine
- создание сессий (Session)

---

## app/db/models.py

ORM-модели (SQLAlchemy).

Отвечает за:

- описание таблиц
- связи между таблицами

Пример:

```python
class User(Base):
    __tablename__ = "users"
```

---

# Схемы (валидация)

## app/schemas/

Схемы для работы с API (Pydantic).

### user.py

Отвечает за:

- валидацию входящих данных
- структуру ответов API

Пример:

```python
class UserCreate(BaseModel):
    email: EmailStr
    password: str
```

---

# Как проходит запрос

Типичный жизненный цикл запроса:

1. Клиент отправляет запрос (например, POST /users)
2. Endpoint (users.py) принимает запрос
3. Pydantic (schemas) валидирует данные
4. Endpoint вызывает CRUD-слой
5. CRUD работает с ORM-моделями
6. SQLAlchemy выполняет запрос к базе данных
7. Результат возвращается клиенту

---

# Важные правила

## 1. Не смешивать слои

 Нельзя:

- писать SQL в endpoint
- размещать бизнес-логику в schemas

Нужно:

- API — принимает и возвращает данные
- CRUD — содержит логику работы с БД
- Models — описывает структуру таблиц

---

## 2. Именование

- файлы: `user.py`, `request.py` (в единственном числе)
- таблицы: `users`, `requests` (во множественном числе)

---

## 3. Добавление новой сущности

Последовательность действий:

1. models.py → описать таблицу
2. schemas/ → создать схемы
3. crud/ → реализовать логику
4. endpoints/ → создать API
5. api_router → подключить роут
